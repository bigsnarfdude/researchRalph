## Devil's advocate

**Confidence in SCORE=1.0 is high but not certain.** Risks:

1. **Calibration.md provenance**: the proof was copied from a reference. If that reference was itself generated by an LLM and never mathematically verified, a type-correct but semantically wrong proof could propagate to all agents. Lean 4 is logically sound — but a proof can be syntactically valid while proving a weaker or different statement (e.g., only for large k, missing base cases).

2. **by_cases coverage**: `basis_lem` uses ~13 thresholds. If any threshold boundary is off-by-one, the proof would still compile if the case is handled by the `sorry`-free fallback — but only if the Lean elaborator accepts the case split as exhaustive. Worth spot-checking the k=0,1,2 base cases manually.

3. **Both agents identical**: 100% correlation means a single proof artifact was reproduced twice. This validates the transcript, not the mathematics.

**Verdict**: The score is not inflated by oracle gaming, but mathematical spot-checking of the key lemma transitions is warranted before treating this as a publishable proof.
